# Source Reliability + Risks

Honest accounting of each connector. **Reddit and HN are the only sources you can
trust to "just work" without setup or fragility.** Everything else is best-effort.

## Reddit — RELIABLE
- **How:** PRAW with read-only application credentials (free).
- **Auth:** `REDDIT_CLIENT_ID` + `REDDIT_CLIENT_SECRET` env.
- **Risks:** Per-app rate limit (rare to hit at hackathon volumes).
- **Demo verdict:** Use as primary.

## Hacker News — RELIABLE
- **How:** Algolia public search API (`hn.algolia.com/api/v1/search`).
- **Auth:** None.
- **Risks:** None worth listing.
- **Demo verdict:** Use as primary.

## Facebook — FRAGILE, BUT THE MAIN TARGET
- **How:** Playwright + Chromium, navigate to `facebook.com/search/posts/?q=...`,
  scroll, scrape `[role="article"]` DOM nodes. Engagement counts via regex on
  visible text — best-effort, not authoritative.
- **Auth:** `info/cookies.json` exported from a logged-in browser session.
- **Known fragilities:**
  - Facebook rotates DOM class names and `aria` patterns. If a fetch returns
    0 posts but the page loads, the selectors need updating.
  - Cookies expire silently. No explicit failure — just empty results.
  - Heavy: spawns Chromium per fetch. Don't run more than ~3 FB queries per run.
  - Account safety: scraping detection can flag/disable the account. **Use a
    throwaway account.**
- **Mitigations in code:** Returns `[]` on any failure. Agent loop treats this
  as "low recall" and falls back to other sources.
- **Legacy path preserved:** `python main.py {scrape,process,summarize}` runs
  the original screenshot + OCR pipeline (richer engagement extraction).
- **Demo verdict:** Showcase if cookies are fresh and selectors haven't drifted.
  Have Reddit + HN running as backup.

## Twitter / X — FRAGILE, AWAITING CREDS
- **How:** `twikit` library (unofficial endpoints, guest-token / cookie auth).
- **Auth options:**
  1. `info/x_cookies.json` exported from logged-in browser (preferred).
  2. `X_USERNAME` + `X_PASSWORD` + `X_EMAIL` env (twikit will log in once and
     persist cookies).
- **Known fragilities:**
  - X / xAI break unofficial endpoints regularly. Expect breakage every few weeks.
  - Login challenges (email codes, captcha) can block the headless flow.
  - Rate limits hit fast on guest tokens.
  - Risk of account suspension. **Use a throwaway account.**
- **Status in this repo:** Connector skeleton wired in. Will return `[]` until
  credentials or cookies are provided. No live integration testing has been run.
- **Demo verdict:** Disabled by default in the UI. Enable only after a successful
  manual login round-trip.

## Instagram — FRAGILE, AWAITING CREDS
- **How:** `instaloader` library, hashtag search.
- **Auth options:**
  1. `info/ig_session_<username>` session file generated by a prior successful login.
  2. `IG_USERNAME` + `IG_PASSWORD` env (will log in once and save the session).
- **Known fragilities:**
  - IG rate-limits aggressively. Anonymous requests are throttled within a
    handful of calls.
  - Login can trigger 2FA / device challenge — not handled headlessly.
  - Hashtag pages return only top-public posts; captions are sometimes empty.
  - High risk of session bans for automation patterns. **Use a throwaway account.**
- **Status in this repo:** Connector skeleton wired in. Will return `[]` until
  credentials or a session file are provided. No live integration testing has
  been run.
- **Demo verdict:** Disabled by default in the UI. Enable only after a successful
  manual session bootstrap.

## What the agent does when a source fails
- Failed connector calls return `[]` and do not raise.
- Agent loop emits a `low_recall` event if total post count < 6 and reissues
  the seed query on remaining working sources.
- A single broken source never kills a run.

## TL;DR for demo / hackathon
- **Reliable:** Reddit, HN. Always on.
- **Real but fragile:** Facebook (main target). Needs fresh cookies.
- **Stubbed, awaiting creds:** Twitter/X, Instagram. UI toggles exist; will
  fire when env vars or cookie files are populated.
